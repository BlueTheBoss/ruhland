## 2025-02-14 - [Sed /e flag and shell command injection]
**Vulnerability:** Command injection vulnerabilities were identified in both the Yad-based settings script (`settings/ruhland-settings`) and the Lua configuration helper (`dots/.config/hypr/hyprland/lib/init.lua`). In the settings script, GNU `sed`'s `/e` modifier allowed arbitrary code execution via inputs. In the Lua helper, `os.execute` ran shell commands with unescaped, unvalidated path strings.
**Learning:** Shell commands constructed by string concatenation of unvalidated variables (even from semi-trusted UI forms) represent a high security risk. GNU `sed` contains powerful features like `/e` that interpret and execute replacement strings via `/bin/sh`.
**Prevention:** Always sanitize and strictly validate inputs using a narrow allowlist regex (e.g. `^[0-9.]+$` for floating-point values) before interpolation. Where possible, utilize native language constructs (such as Lua's `io` library) instead of spawning shell sub-processes like `os.execute("echo ...")`.
